lex-agents requires a retrieval pipeline that can:
1. Find relevant legal chunks across BOE and EUR-Lex corpora
2. Handle both semantic similarity queries ("¿qué dice el CRR sobre capital?")
   and keyword-precise queries ("artículo 92 apartado 1 letra a")
3. Operate in Spanish and English without separate indexes
4. Support filtered retrieval (jurisdiction, in_force, document_type)

## Intended Decision

### Contextual Retrieval (Anthropic, 2024)

Each chunk is enriched with a 50-100 word context paragraph situating it
within its parent document, generated by `claude-haiku-4-5` with prompt
caching of the parent document text. The concatenation of `chunk_text +
contextual_summary` is embedded and indexed.

Expected improvement: ~49% reduction in retrieval failure rate vs. naive
chunking (per Anthropic's published benchmarks).

### Hybrid Search (dense + sparse)

- **Dense vector**: BAAI/bge-m3, 1024-dim, cosine similarity
- **Sparse vector**: BAAI/bge-m3 SPLADE output, dot product
- **Fusion**: Reciprocal Rank Fusion (RRF) at query time in Qdrant

Hybrid search handles the dense-sparse tradeoff inherent in legal text:
semantic queries benefit from dense; exact article citations benefit from
sparse/keyword matching.

### Reranking

After hybrid retrieval (top-50), apply BAAI/bge-reranker-v2-m3 cross-encoder
reranker to select final top-K (default K=10) chunks passed to the agent.

### Payload filtering

Qdrant payload filters applied before vector search:
- `jurisdiction: "EU" | "ES"`
- `in_force_at_indexing: true` (configurable; can include historical)
- `document_type` (list)
