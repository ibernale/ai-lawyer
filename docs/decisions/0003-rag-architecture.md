# 0003 — Arquitectura RAG: Contextual Retrieval + Hybrid Search + Reranking

**Status:** Accepted
**Date:** 2026-05-10

## Context

lex-agents requires a retrieval pipeline that can:

1. Find relevant legal chunks across BOE and EUR-Lex corpora
2. Handle both semantic similarity queries ("¿qué dice el CRR sobre capital?")
   and keyword-precise queries ("artículo 92 apartado 1 letra a")
3. Operate in Spanish and English without separate indexes
4. Support filtered retrieval (jurisdiction, status, document_type)

Legal text has a dual retrieval challenge: dense/semantic search excels at
conceptual questions ("¿qué exige el CRR en materia de CET1?") but misses
exact article citations; keyword/sparse search excels at citations but fails
on paraphrasing and synonyms. A hybrid approach with cross-encoder reranking
is required.

## Decision

### 1. Contextual Retrieval

Each chunk is enriched with a 50-100 word context paragraph generated by
`claude-haiku-4-5-20251001` (with prompt caching of the parent document) before
embedding. The embedding input is `context_text + "\n\n" + chunk_text`.

This approach is based on Anthropic's published research (2024):

- Contextual Retrieval alone reduces retrieval failure rate by **49%**
- Contextual Retrieval + BM25 reduces it by **67%**
- We achieve the 67% target using BGE-M3 sparse vectors (SPLADE-style)
  instead of a separate BM25 index, maintaining model-family coherence.

Prompt caching (ephemeral, min 1024 tokens) is applied to the full document
system message. After the first chunk of each document, subsequent chunks
reuse the cached context — this reduces Haiku API cost by ~80-90% per document.

### 2. Embedding Model: BAAI/bge-m3

- **Dense**: 1024-dim cosine vectors (HNSW in Qdrant)
- **Sparse**: SPLADE-style `lexical_weights` output from the same model
- **Why BGE-M3**: multilingual ES+EN coverage in a single model, state-of-the-art
  on BEIR, open weights (deployable on-prem), generates dense+sparse in one pass

Single model = single forward pass = no dual-model complexity at index/query time.

### 3. Qdrant Named Vectors

Collection `lex_legal_docs` uses:

- Named vector `"dense"`: `VectorParams(size=1024, distance=Cosine)`
- Named sparse vector `"sparse"`: `SparseVectorParams(index=SparseIndexParams())`

Payload = all `ChunkMetadata` fields + `text` + `context_text`.

### 4. Hybrid Search with RRF

Query time:

1. Embed query with BGE-M3 (dense + sparse in one call)
2. Dense search: top-50 by cosine
3. Sparse search: top-50 by dot product
4. **Reciprocal Rank Fusion** (RRF): merge → top-30

RRF formula: `score(d) = Σ 1/(k + rank(d, list))` with `k=60` (standard).
k=60 dampens rank differences and is robust to positional noise.

Window: dense=50, sparse=50, k_rrf=30 (then reranked to top-10).

### 5. Cross-Encoder Reranking

`BAAI/bge-reranker-v2-m3` applied on top-30 → final top-K (default K=10).
Same BAAI model family as the embedder, ensuring coherent semantic space.
Lazy-loaded; `PassthroughReranker` fallback for test environments (no 1.1GB download).

### 6. Query Rewriting

`LegalQueryRewriter` (Haiku) expands legal acronyms and synonyms before retrieval:
CRR → Reglamento (UE) 575/2013, CET1 → capital de nivel 1 ordinario, etc.
Temperature=0, structured JSON output.

### 7. Context Assembly

`ContextAssembler` formats chunks as:

```
[REF:1]
<hierarchy_path>
<context_text>

<text>

[REF:2]
...
```

and returns a `CitationMapping` list for the citation verifier (Fase 3).

## Consequences

- **Good**: single BGE-M3 model covers dense+sparse without BM25 library
- **Good**: PassthroughReranker makes CI fast without model downloads
- **Good**: prompt caching makes per-document contextualisation cost-effective
- **Trade-off**: BGE-M3 is ~570MB; must be mounted/cached in prod
- **Trade-off**: Cross-encoder reranker is ~1.1GB; disabled in CI, enabled in prod
- **Open (Fase 3)**: optimal final K given claude-opus-4-7's 200k context window

## Alternatives considered

| Alternative                             | Reason rejected                                                        |
| --------------------------------------- | ---------------------------------------------------------------------- |
| Cohere Embed v3                         | Vendor lock-in, no open weights for on-prem                            |
| OpenAI text-embedding-3-large           | Same, plus no integrated sparse output                                 |
| Separate BM25 (Elasticsearch/BM25Okapi) | Extra infra dependency; BGE-M3 sparse achieves the same quality        |
| ColBERT late-interaction                | Not supported natively in Qdrant at time of writing; higher complexity |
