# Admin Guide — lex-agents v0.4.0

Guide to the `/admin` section of the lex-agents web interface, covering
all tabs, operations, and role permissions.

---

## Access

Navigate to `http://localhost:3000/admin` (or the production URL).

**Required role:** `operator` or `admin`. Users with role `user` are
redirected to the home page.

**Login:** `POST /auth/token` with your credentials. The JWT is stored
in `sessionStorage`. Tabs are accessible immediately.

---

```
┌─────────────────────┐
│ Sistema             │ ← system status badge (OK / KILL ACTIVE)
│─────────────────────│
│ Ops Center          │ /admin/ops
│ Governance          │ /admin/governance
│ Audit Trail         │ /admin/audit-trail
│─────────────────────│
│ Costs & FinOps      │ (coming Fase 9)
└─────────────────────┘
```

The **system badge** at the top of the sidebar shows whether the global
kill switch is engaged (`KILL ACTIVE` in red) or the system is operating
normally (`OK` in green).

## Top bar

| Element              | Description                                        |
|----------------------|----------------------------------------------------|
| Username + role badge | Logged-in user and their role                    |
| Bell icon            | Notification center — shows unread count badge     |
| Global Kill Switch   | Admin-only button to engage/release global stop    |

### Notification bell

Click the bell to open the **Notifications Drawer** (slides in from the right).

- Badge shows unread count (hidden when 0; caps at `9+`)
- Count refreshes every 30 seconds automatically
- Notifications are generated by: kill switch events, Grafana alerts,
  Dagster pipeline failures, and manual webhook ingestion

## Governance (`/admin/governance`)

**Minimum role:** operator (read proposals), admin (approve/reject/pause)

### Source management

Each data source (`boe`, `eurlex`, `cendoj`, `inlabs`) can be:

- **Active** — normal operation
- **Paused** — no new ingestion; existing docs still searchable
- **Error** — ingestion pipeline failed; auto-paused

Pause/resume actions require a written reason and are logged in the
audit trail.

### Prompt evolution proposals

When the system auto-generates an improved prompt for an agent, a
proposal appears here as a pull request reference. Admins can:

- **Approve** — merge the PR; new prompt becomes active
- **Reject** — close the PR with a reason
- **Request changes** — add a review comment without closing

All decisions are logged in the audit trail with actor, timestamp, and reason.

## Audit Trail (`/admin/audit-trail`)

**Minimum role:** operator (read-only)

Shows a chronological log of all admin actions. Entries include:

| Field         | Description                               |
|---------------|-------------------------------------------|
| `action_type` | `source.pause`, `kill_switch.engage`, etc.|
| `actor`       | Username who performed the action         |
| `actor_role`  | Role at the time of the action            |
| `target_type` | `source`, `kill_switch`, `feature_flag`   |
| `target_id`   | Specific target identifier                |
| `reason`      | Free-text reason provided                 |
| `timestamp`   | UTC ISO-8601                              |
| `checksum`    | SHA-256 chain link for tamper detection   |

The **Verify Chain** button runs `GET /api/v1/admin/audit-trail/verify`
and displays whether the checksum chain is intact.

## Notifications Drawer

Accessed via the bell icon in the top bar.

### Filters

| Filter   | Shows                                      |
|----------|--------------------------------------------|
| All      | All notifications                          |
| Critical | Red-category (kill switch, service down)   |
| Warning  | Amber-category (latency, verification)     |
| Info     | Blue-category (routine events)             |

### Actions

- **Mark read** — marks a single notification read (button visible on unread items)
- **Mark all read** — marks all unread notifications read in one click

### Sources

| Source    | Trigger                                        |
|-----------|------------------------------------------------|
| `system`  | Kill switch events (automatic)                 |
| `grafana` | Tier 1/2 alerts via webhook `POST /ingest`     |
| `dagster` | Pipeline failure events via webhook            |
| `langfuse` | Evaluation alerts (planned — see ADR-0030)   |

## Global Kill Switch

The most powerful action available. When engaged:

1. All `POST /api/v1/consult` requests return `503 SYSTEM_KILLED`
2. A `critical` notification is created automatically
3. An audit trail entry is written with actor, reason, and timestamp
4. The sidebar badge changes to `KILL ACTIVE` (red)

To engage, click **"Global Kill Switch"** in the top bar, enter a
mandatory reason, and confirm. The same button becomes **"Release Kill
Switch"** (green) when active.

Only `admin` role can engage or release kill switches.
